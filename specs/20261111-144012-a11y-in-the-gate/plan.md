# Plan: The gate asserts accessibility, not just a Storybook panel

## Technical context

- **The engine is already here.** `axe-core@4.14.0` resolves in the tree today through `@storybook/addon-a11y`. Nothing new has to be installed; it becomes a direct `devDependency` with a `^4.14.0` range so it cannot vanish when that addon's own dependencies change (FR-003).
- **No wrapper library.** `jest-axe` and `vitest-axe` each bring their own matcher and their own version of `axe-core`, which would mean two copies and a second expectation API. `axe-core`'s `run()` returns `{ violations }` and is enough: a helper does `const { violations } = await axe.run(container)` and asserts the array is empty, formatting each violation as `<rule id>: <help> (<n> node(s)) — <first target>` so a failure says what broke and where. One file, no new matcher, one axe (FR-002, FR-005).
- **Where the helper lives: `test-utils/axe.ts` at the repo root**, exporting `expectNoViolations(container: HTMLElement)`. The obvious spot is `components/test-utils/`, and it is rejected on purpose: `CLAUDE.md` says `components/<name>/` "holds, and only holds" the seven files of a component, and while a sibling utility directory arguably does not breach a rule about a component's own directory, settling that argument would mean editing that paragraph. A root directory needs no such edit and no reading of a rule against its author. `vite.config.ts`'s `include` is `components/**/*.test.tsx`, so the helper is not collected as a test wherever it sits, and a component test imports it as `../../test-utils/axe`.
- **jsdom's limits, stated rather than papered over.** axe in jsdom has no layout and no computed colour, so `color-contrast` cannot run and reports as incomplete, not as a pass. The helper asserts on `violations` only and switches `color-contrast` off explicitly in its axe options, which is FR-002's exception: the output then records that the rule did not run rather than letting a reader believe it passed. The docs say contrast is not covered here (FR-007, spec § Out of scope).
- **What each component's test covers.** Default rendering plus each `code` variant the contract declares: `badge` 4 tones; `button` 3 sizes × 2 variants, plus the `iconBefore` slot filled, and not the design-only `state` axis, which the code must not carry; `card` `padding` default and `none`, each with a `Card.Header` inside, which is also `card-header`'s coverage since it is only rendered in composition. A loop over the variant list per component, one axe run each (FR-001).
- **Unknown until it runs: whether the three components are clean.** If any has a real violation, FR-006 says fix the component, not the test. The plan cannot promise which, so T004 runs the helper against `badge` before any further test is written, and the pull request lists what it found. **If a violation turns out to need a design decision rather than a mechanical fix, it is split into its own issue and this one ships the gate** — a ticket that quietly grows a design argument is the thing `Keep tickets small` exists to stop.
- **The scaffold.** `scripts/scaffold-component.mjs`'s `${name}.test.tsx` template gains the import and one `expectNoViolations` call alongside its existing class assertion, with the relative path from a component directory (`../../test-utils/axe`). `CLAUDE.md` already records the coupling `components/badge/*` → the scaffold templates, so badge's test and the template stay the same shape (FR-004).

## Surfaces touched

- `test-utils/axe.ts` — new file at the repo root, the shared `expectNoViolations` helper. A new top-level directory, so `docs/architecture.md`'s layout description names it; CI's `Check docs/` step holds the directory list.
- `components/badge/badge.test.tsx`, `components/button/button.test.tsx`, `components/card/card.test.tsx` — one accessibility test each, over the variants listed above.
- `components/badge/*`, `components/button/*`, `components/card/*` — changed only if the suite finds a real violation; FR-006 governs, and the pull request lists each finding and its fix.
- `scripts/scaffold-component.mjs` — the test template gains the `../../test-utils/axe` import and the call. This is `CLAUDE.md`'s `components/badge/*` → scaffold-templates coupling: badge's test and the template must stay the same shape.
- `package.json` — `axe-core` added to `devDependencies`; `package-lock.json` updated by the install.
- `docs/testing.md` — `What is tested` says each component has an axe assertion and what it covers; `Adding a test` says a new component's test calls `expectNoViolations`, and names the helper's path.
- `README.md` — the Storybook paragraph's accessibility sentence distinguishes the addon's panel from the gate's assertion.
- `docs/architecture.md` — the `.storybook/` sentence stops implying the addon is the accessibility check, and the layout description names `test-utils/`.
- `CLAUDE.md` — says the gate asserts accessibility, beside what the Storybook addon shows. The Component directory shape paragraph is deliberately left alone: the helper is at the repo root precisely so that rule needs no amendment. Keep every line inside the file's character cap.
- `.github/workflows/build-check.yml` — no change: it runs `npm run verify`, which runs `npm test`, so `build / ci` keeps its name and no branch ruleset edit is owed.
- `scripts/init.mjs` — read its sweep and removal lists and confirm the new root `test-utils/` needs no entry: the helper holds no `--ads-` reference and no `<!-- init -->` marker. Do not run the script on this checkout, which it renames in place; `init / ci` runs it on the pull request and is what proves the claim. Fix `scripts/init.mjs` here if that check fails.
- cost — none: no workflow trigger, cron, agent fire or scheduled function is added. Roughly a dozen extra axe runs inside the existing `npm test` step, a second or two of an already-billed job.
- `docs/adr/` — none owed. The repo's own `CLAUDE.md` and the fleet's component standard already hold that a component ships an accessibility smoke test; this implements that rather than deciding it. If the build concludes otherwise while working, it says so in the pull request rather than writing one silently.
- none else — no reusable workflow body in [chrisgriffin/workflows](https://github.com/chrisgriffin/workflows) is touched, no required check is renamed, nothing published changes (this package is private and ships no `bin` or export), and no rule is newly stated in a second doc: what the gate runs lives in `docs/testing.md`, and `README.md`, `CLAUDE.md` and `docs/architecture.md` each already summarise it, so they are corrected rather than newly duplicated.
