# Testing

The tests prove that the token build emits what the components may use and nothing else, that each component renders what its contract says, and that the engine's gate agrees with both.

## The gate

- CI runs this repo's gate on every PR; the commands are the `run:` steps of
  its CI workflow in `.github/workflows/`.
- A PR merges only when that gate is green.
- Run the same commands locally before pushing. A failing test is fixed in
  the code, never by weakening the assertion.
- A behavior change starts with a test that fails without it.

## Running tests

`build-check.yml` runs `npm run verify`, which is these seven in order:

- `npm run build:tokens` — Terrazzo over `tokens/json`, then the primitive inlining; the later steps read its output.
- `npm run typecheck` — `tsc --noEmit` over the program `tsconfig.json` includes: `components`, `.storybook` (named by its `.storybook/**/*` glob, since `tsc` skips a dot-directory a bare name reaches), `test-utils` (the gate's own tests), `types`, `vitest.setup.ts`, and from `tokens/scripts` only `build-manifest.d.mts`, its `.mjs` scripts being plain ESM outside the program; a type error fails it, naming the file and the line.
- `npm run prettier:check` — Prettier over everything `.prettierignore` does not exclude, in the shared `@chrisgriffin/config/prettier` style.
- `npm run lint` — ESLint from `eslint.config.mjs`, which spreads `@chrisgriffin/config/eslint` first.
- `npm run lint:styles` — Stylelint over every `.css` file: a color, fill or stroke, font family, size or weight, line height, border radius, margin or padding, gap, or transition or animation duration or timing value that is not a `--ads-*` property fails (other sizes, such as `width`, are not checked), and so does a property name the built CSS does not define.
- `npm run drift:verify` — `design-delta verify`: every contract validated, then compared with its component and stylesheet; an error-severity finding fails it, and a component no contract references is one (`coverage/uncontracted-component`, raised to `error` in `design-delta.json`).
- `npm test` — `node --test` over `tokens/scripts/*.test.mjs`<!-- init --> and `cli/*.test.mjs`<!-- /init -->, then `vitest run` over `components/**/*.test.tsx` and `test-utils/**/*.test.ts` in jsdom (`test-utils/contract-coverage.test.ts` in Node, since it runs the engine).

`storybook-check.yml` is the Storybook gate, `storybook / ci`, and the only check that builds this checkout's Storybook: `npm run build:tokens && npm run build-storybook`, the Storybook build also running the engine's audit for the Design Drift page. Run it with `verify` before pushing a change to a component, a story or `.storybook/`.

`init-check.yml` first runs `cli/create.mjs` with sample values on a new temp folder, with no token, SSH disabled and npm 11 on the path, so the check fails when a created system does not install without credentials, does not pass its own gate, or still holds `cli/`, `scripts/init.mjs` or the template's `specs/`, when its `package.json` keeps the create command's name, `bin` or `files`, is not `private`, or `publish.yml` survives (#79), when its README intro is not `The <name> design system.` or its `LICENSE` still names the template's copyright holder (#49), when its `package-lock.json` differs from the template's past the name and the removed `bin`, or when `npm@10 ci --dry-run`, Node 22's npm, refuses that lock file (#44). It then drops the nested `yaml-to-momoa` entry from the PR checkout's lock file, as an npm 11 install does, and runs `scripts/init.mjs` with sample values on that checkout, renaming it in place, as `init / ci`: the script runs `npm run verify` and then `npm run build-storybook` itself on the renamed checkout, and the check fails when the script, `cli/` or `specs/` survives, when `package.json` or `publish.yml` fail the same #79 check, when `LICENSE`, `package.json`'s `description` or the README intro does not carry the `--author` and `--description` it was given, or the README still describes the template (#49), when an `--ads-` reference is left outside `specs/`, `node_modules` and `storybook-static`, when the lock file it leaves is not the committed one renamed (#44), or when a Markdown file outside those still holds an `<!-- init -->` marker or names the script, `cli/create.mjs` or its workflow. Both runs fail when the copy has no `.claude/skills/setup-system/SKILL.md`, and the init run when its closing line does not name `/setup-system` (#59).

## What is tested

- `scripts/mcp.test.mjs` — `npm run mcp` spoken to over stdio (#94): `initialize` names the package, `tools/list` holds the three own tools and design-delta's; `get_component_usage` gives `badge`'s folder, exports and stories, and an unknown id (`../tokens` included) is an error listing the known ones; `get_theme_tokens` gives a color different values in light and dark and a radius one value; `get_rules` gives `CLAUDE.md`'s invariants and directory shape and nothing else; `get_contract` is answered by design-delta; an unknown tool is an error naming every tool, the own and design-delta's; and in a copy with no `node_modules` the own tools still answer while a design-delta tool is an error naming it. In copies of the server: `null`, a number, a string, a boolean, an array, `{}` and a request with no method are each `-32600` and the next request is still answered; with a stand-in design-delta that hangs on the handshake or on a call, the own tools and `ping` still answer and the design-delta call is an error naming the timeout; a stand-in that exits before its stdout drains still has its reply read; a stand-in tool named like an own tool is dropped from `tools/list`; with no design-delta an unknown tool names the own tools and why design-delta's are missing; `get_component_usage` reads every export form an `index.ts` can use (per-name `type`, `as` aliases, `default as`, `export *` and `export * as`, declarations, `export default`); and forty replies all arrive whole, with no `process.exit` in the server.
- `tokens/scripts/tokens.test.mjs` — the built CSS declares no `--ads-primitive-*` property, has no `var()` left and declares more than 40 `--ads-*` properties, both themes are present and differ, and every manifest value is a literal.
- `tokens/scripts/contrast.test.mjs` — every text pair a component stylesheet sets reaches 4.5:1 (WCAG 2.1 AA, normal text) in both themes, the colours read from the build manifest; a pair below fails, naming the stylesheet, the selector, both tokens, the theme and the ratio (#60). The pairs are read from each `components/**/*.module.css`, not listed: the first class is the root and each other class a modifier over it, the cascade is followed as a browser does (root, modifier, the root's `:state`, the modifier's `:state`), text with no background or a `transparent` one sits on `bg.canvas`, and an accent token used as text is also checked on `bg.canvas`. A selector it does not model (anything but a top-level `.class` and its nested `&:state` blocks) or a value it cannot resolve throws, so no pair goes unchecked silently.
- `tokens/scripts/inline-primitives.test.mjs` — `inlinePrimitives` on its own, without running the build: a primitive reference becomes the primitive's value, primitive declarations are gone from the output, an undeclared primitive throws, a primitive aliasing another inlines to its final value, a reference cycle throws naming it (a self-reference and a cycle nothing references too), a reference with whitespace or a fallback is inlined, a semantic name containing `-primitive-` is left alone, a primitive declared in two blocks throws, and a primitive left in the output in any other form throws.

- `components/<name>/<name>.test.tsx` — each component renders its content and the class its stylesheet keys off, with Testing Library; CSS Module class names are unscoped in tests so an assertion can name them.
- The same files' accessibility tests — `expectNoViolations` from `test-utils/axe.ts` runs axe-core over the rendered DOM and fails on any violation, naming the rule, how many elements broke it and the first one. It covers each component's default and every variant its contract gives code, read from the contract rather than typed into the test: `variantCases` from `test-utils/variants.ts` turns each code-side enum prop's values into one case per combination, titled by value, so a value added to a contract is checked with no test edit, and an enum marked `"code": "none"` gets no case. Today that is `badge`'s four tones, `button`'s three sizes by two variants plus the `iconBefore` slot, and `card`'s two paddings, each with a `Card.Header`, which is also `card-header`'s coverage. `color-contrast` is switched off: jsdom has no layout and no computed colour, so axe cannot measure it, and rules that need layout report incomplete rather than failing. Contrast is checked by `tokens/scripts/contrast.test.mjs` instead, above; the Storybook accessibility panel (`@storybook/addon-a11y`) also shows findings in the browser and fails nothing.
- `test-utils/a11y-coverage.test.ts` — the gate enforces the rule that every component test calls `expectNoViolations`: it reads each `components/**/*.test.tsx` and fails, naming the file, when one never calls it (comments do not count, and importing it is not calling it). It also fails, naming the folder, when a folder under `components/` holds a component source file but no `.test.tsx`; the check is per folder, so `card-header.tsx` is covered by `card.test.tsx`. And it fails, naming the contract and the folder's test files (or saying the folder has none), when a contract with a code-side enum sits in a folder where no test imports that contract and passes the import to `test.each(variantCases(…))` with a case that calls `expectNoViolations`, so no variant list is kept by hand and every case reaches axe (#57); it also checks `variantCases` itself: every combination, no case for a design-only enum, one `defaults` case when there is no enum or no `props`, numeric values, `_`-prefixed keys skipped, and a throw naming the prop for a code-side enum whose `values` is missing, empty or holds no string or number. Every contract under `components/` must give at least one case: one that would give none fails, naming the contract file and the prop (#71).
- `test-utils/contract-coverage.test.ts` — the gate enforces the rule that every component has a contract: it copies the config, `components/` and `tokens/` into a temp directory, adds a component no contract references, runs the installed `design-delta`, and fails unless `audit` reports `coverage/uncontracted-component` at `error` and `verify` exits non-zero naming it. Lowering that rule's severity in `design-delta.json` fails it. It also guards the typecheck: it asks TypeScript which files `tsconfig.json`'s program holds and fails unless both `test-utils/*.test.ts` files are among them, so dropping `test-utils` from `include`, or an `exclude` that reaches it, fails `npm test`.
- Keyboard, which axe does not check: axe reads the markup and never presses a key, so `button.test.tsx` drives Button with `userEvent` the way a keyboard user would. Tab reaches an enabled Button, Enter and Space each fire its `onClick` exactly once, and a disabled Button is skipped by Tab and fires nothing on Enter or Space. Button is the only interactive component, so Badge and Card have no keyboard tests.
- `design-delta verify` — not a test file but the gate's own check: the contract's props against the component's, its anatomy against the rendered tree, its token bindings against the stylesheet.

## Adding a test

- A component's test is `components/<name>/<name>.test.tsx`; `vite.config.ts` collects `components/**/*.test.tsx` and `test-utils/**/*.test.ts` only.
- A component's test also calls `expectNoViolations` from `../../test-utils/axe` on each variant its contract gives code, through `test.each(variantCases<Props>(contract))` on its imported `<name>.contract.json`; `npm run scaffold` writes that test for you, and `test-utils/a11y-coverage.test.ts` fails `npm test` on a test file without one, and on a component folder with no test file at all. A violation is fixed in the component, never by switching a rule off.
- A token test is a `.test.mjs` beside the scripts under `tokens/scripts/`, on `node:test`.
- `vitest.setup.ts` loads jest-dom's matchers and cleans the DOM after each test. It is in the TypeScript program, so `typecheck` sees those matchers on every test file.
